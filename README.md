# Terrarium

Terrarium is a modern Android plant-store app for discovering houseplants, choosing the right plant for a space, completing a demo purchase flow, and keeping up with plant care.

The app is built with **Kotlin**, **Jetpack Compose**, and **Material 3**. It uses a local **Room** database for catalog, cart, wishlist, order, and care-reminder data, with seed data included so the app can be explored immediately after launch.

## Features

- Browse a seeded plant catalogue with product details, categories, sizes, care information, ratings, and reviews

- Search, sort, filter, and shop by space, including living rooms, bedrooms, offices, balconies, and small spaces

- Take the Plant Match Quiz for rule-based plant recommendations based on the user's preferences

- Save products to a wishlist and manage cart items

- Complete a local demo checkout flow with delivery and payment options

- View order history and follow order progress through a visual tracking timeline

- Read plant care guides

- Create, complete, and delete watering and fertilizing reminders

- Use separate customer and store-admin views for the demo experience

- Load plant artwork from remote image URLs with Coil

> **Scope:** This repository currently implements a local/demo shopping experience. Checkout, payments, authentication, inventory, and order fulfillment are not connected to a production commerce backend.

## Getting started

1. Clone the repository:

   ```bash
   git clone https://github.com/Vinayak-coding/terrarium-plant-store.git
   cd terrarium-plant-store
   ```

1. Open the project in Android Studio.

1. Allow Android Studio to sync the Gradle project and install any missing SDK components.

1. Select the `app` run configuration and launch it on an emulator or connected Android device.

The repository does not currently include a Gradle wrapper. If you build from the command line, use a compatible Gradle installation or generate the wrapper from Android Studio before running the commands below.

## Build and test

From the repository root, use Android Studio's **Build** and **Run** actions, or a compatible Gradle installation:

```bash
gradle assembleDebug
gradle test
```

Useful test targets include:

```bash
gradle :app:testDebugUnitTest
gradle :app:testDebugUnitTest --tests com.example.ExampleRobolectricTest
gradle :app:testDebugUnitTest --tests com.example.GreetingScreenshotTest
```

The test suite covers seeded data, currency formatting, navigation routes, default customer/admin profiles, delivery options, and screenshot rendering.

## Configuration

### Firebase and Google services

`app/google-services.json` is present for the current development configuration, and the Google Services Gradle plugin is enabled. For a different Firebase project, replace that file with the configuration generated by Firebase for the Android application ID.

### Secrets

`.env` is intentionally ignored by Git. Use `.env.example` as the template for local secrets. If Gemini-backed functionality is enabled in a future integration, configure the required key through the Android Studio/AI Studio secrets workflow rather than committing it to the repository.

## Architecture and project layout

The app follows a lightweight MVVM-style structure:

```
app/src/main/java/com/example/
├── MainActivity.kt
├── data/
│   ├── local/          # Room database, DAOs, converters, and seed data
│   ├── model/          # Products, orders, reminders, quiz, and user models
│   └── repository/     # Repository and demo commerce operations
└── ui/
    ├── components/     # Shared Compose components and navigation
    ├── screens/        # Home, catalogue, quiz, cart, orders, guides, etc.
    ├── theme/          # Colors, typography, and Compose theme
    └── viewmodel/      # TerrariumViewModel and factory
```

### Local data flow

- `AppDatabase` defines the Room database.

- `TerrariumDaos` exposes reactive `Flow` queries and suspend operations.

- `SeedData` provides the initial plant catalogue.

- `TerrariumRepository` coordinates catalogue, cart, wishlist, orders, and reminders.

- `TerrariumViewModel` exposes state to Compose screens and handles user actions.

- `MainActivity` wires the screens together with Compose Navigation.

## Demo data and behavior

On first launch, the local database is populated with the built-in plant catalogue. Orders placed from checkout are demo orders stored locally and can be advanced through the admin dashboard. The first-time customer profile and default admin profile are also defined in the model layer for the demo experience.

To reset the demo state, clear the app's storage from Android settings or uninstall and reinstall the app.

## Security notes

- Do not commit `.env`, signing keys, passwords, API keys, or other secrets.

- Release signing reads `KEYSTORE_PATH`, `STORE_PASSWORD`, and `KEY_PASSWORD` from the environment.

- The included `google-services.json` should only be used with the Firebase project it belongs to; replace it when distributing the app under a different Firebase project.
